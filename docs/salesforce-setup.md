# CaseShelf のデータをSalesforceに保存するための設定手順

CaseShelf の投稿・写真・利用者などは、Salesforce に保存します。
この手順書は、**Salesforce のシステム管理者**が、そのための入れ物（カスタムオブジェクト）と権限を作るためのものです。

所要時間の目安は 1〜2 時間です。**項目の「API 参照名」は、この手順書と一字一句同じにしてください**（アプリはこの名前でデータを読み書きします）。

> 前提: 「Salesforceでログイン」と「物件Noで商談を検索」の設定（接続アプリケーションのOAuth範囲に `api`、CORS の許可リスト）は済んでいるものとします。README の「Salesforceでログイン」を参照。

---

## 全体像

| 作るもの | 用途 | 共有設定（組織の共有設定） |
|---|---|---|
| カスタムオブジェクト **CaseShelf投稿**（`CaseShelf_Post__c`） | 投稿（案件名・説明・タグ・物件No・商談URL・写真の並び） | **公開/参照のみ** |
| カスタムオブジェクト **CaseShelf利用者**（`CaseShelf_User__c`） | CaseShelf の利用者（表示名・メール・権限・状態） | **公開/参照・更新可能** |
| カスタムオブジェクト **CaseShelf保存**（`CaseShelf_Save__c`） | 保存（ブックマーク） | **非公開** |
| カスタムオブジェクト **CaseShelf利用依頼**（`CaseShelf_Request__c`） | 未登録の人からの利用登録の依頼 | **非公開** |
| カスタムオブジェクト **CaseShelfリアクション**（`CaseShelf_Reaction__c`） | 投稿へのリアクション（絵文字） | **公開/参照のみ** |
| 権限セット **CaseShelf利用者**（`CaseShelf_Member`） | CaseShelf を使う全員に付ける | – |
| 権限セット **CaseShelf管理者**（`CaseShelf_Admin`） | CaseShelf の管理者に追加で付ける | – |

- 写真とプロフィール画像は、Salesforce の**ファイル**として、投稿・利用者のレコードにひも付けて保存されます（新しいオブジェクトは不要）。
- 投稿者は、投稿レコードの「作成者」で記録されます。リアクションした人も、リアクションレコードの「作成者」で記録されます。
- 写真は保存時に長辺1600pxのJPEG（1枚おおよそ0.3〜0.6MB）に縮小されるため、ファイル容量は1投稿あたり約3MB以下です。

## 1. カスタムオブジェクトを作る

**設定 → オブジェクトマネージャ → 作成 → カスタムオブジェクト** で、次の5つを作ります。
共通の設定:
- 「検索を許可」「レポートを許可」は任意（オンにしておくと Salesforce 上で探しやすくなります）
- 「リリース状況」は **リリース済み**
- 「新規カスタムタブウィザードを起動」は任意（Salesforce 上でデータを見たい場合はオン）

### 1-1. CaseShelf投稿

| 設定 | 値 |
|---|---|
| 表示ラベル | CaseShelf投稿 |
| 表示ラベル（複数形） | CaseShelf投稿 |
| オブジェクト名（API参照名） | `CaseShelf_Post` （→ `CaseShelf_Post__c` になります） |
| レコード名 | 投稿番号 |
| データ型 | **自動採番**、表示形式 `CS-{000000}`、開始番号 1 |

作成後、「項目とリレーション」→「新規」で次の項目を追加します。

| 項目の表示ラベル | 項目名（API参照名） | データ型 | 設定 |
|---|---|---|---|
| 案件名 | `Title` → `Title__c` | テキスト | 文字数 255、**必須** |
| 案件説明 | `Description` → `Description__c` | ロングテキストエリア | 文字数 32,768、表示行数 5 |
| ハッシュタグ | `Tags` → `Tags__c` | ロングテキストエリア | 文字数 32,768（1行に1つのタグ） |
| 物件No | `PropertyNo` → `PropertyNo__c` | テキスト | 文字数 100 |
| Salesforce案件URL | `SalesforceUrl` → `SalesforceUrl__c` | URL | – |
| 写真 | `Photos` → `Photos__c` | ロングテキストエリア | 文字数 32,768（写真の並び。アプリが管理） |
| 代表写真 | `CoverPhotoId` → `CoverPhotoId__c` | テキスト | 文字数 18（アプリが管理） |
| デザイン担当者 | `DesignStaff` → `DesignStaff__c` | ロングテキストエリア | 文字数 32,768（部門と担当者名。アプリが管理） |

> 「デザイン担当者」は後から追加した項目です。すでに CaseShelf を使っている場合は、この項目だけを追加し、
> 手順3の項目レベルセキュリティで、両方の権限セットに参照・編集の権限を付けてください。
> 追加するまでの間は、投稿画面にデザイン担当者の入力欄が表示されないだけで、ほかの機能はそのまま使えます。

### 1-2. CaseShelf利用者

| 設定 | 値 |
|---|---|
| 表示ラベル | CaseShelf利用者 |
| オブジェクト名（API参照名） | `CaseShelf_User` （→ `CaseShelf_User__c`） |
| レコード名 | 表示名 |
| データ型 | **テキスト** |

| 項目の表示ラベル | 項目名（API参照名） | データ型 | 設定 |
|---|---|---|---|
| メールアドレス | `Email` → `Email__c` | テキスト | 文字数 255、**必須**、**ユニーク**（「大文字と小文字を区別しない」を選択） |
| 権限 | `Role` → `Role__c` | 選択リスト | 値: `member`、`admin`（この順で1行ずつ）。デフォルト値 `member`。「値セットで定義された値に選択リストを限定」をオン |
| 状態 | `Status` → `Status__c` | 選択リスト | 値: `active`、`suspended`。デフォルト値 `active`。「値セットで定義された値に選択リストを限定」をオン |
| プロフィール画像 | `AvatarVersionId` → `AvatarVersionId__c` | テキスト | 文字数 18（アプリが管理） |

> 選択リストの値は、表示ラベルも API 参照名も上の英字のままにしてください（アプリはこの値で判定します）。

### 1-3. CaseShelf保存

| 設定 | 値 |
|---|---|
| 表示ラベル | CaseShelf保存 |
| オブジェクト名（API参照名） | `CaseShelf_Save` （→ `CaseShelf_Save__c`） |
| レコード名 | 保存番号 |
| データ型 | **自動採番**、表示形式 `SV-{000000}` |

| 項目の表示ラベル | 項目名（API参照名） | データ型 | 設定 |
|---|---|---|---|
| 投稿 | `Post` → `Post__c` | **参照関係**（関連先: CaseShelf投稿） | 「参照レコードが削除された場合」→ **この項目の値を空白にします** |

### 1-4. CaseShelf利用依頼

| 設定 | 値 |
|---|---|
| 表示ラベル | CaseShelf利用依頼 |
| オブジェクト名（API参照名） | `CaseShelf_Request` （→ `CaseShelf_Request__c`） |
| レコード名 | 氏名 |
| データ型 | **テキスト** |

| 項目の表示ラベル | 項目名（API参照名） | データ型 | 設定 |
|---|---|---|---|
| メールアドレス | `Email` → `Email__c` | テキスト | 文字数 255、**必須** |
| 状態 | `Status` → `Status__c` | 選択リスト | 値: `pending`、`approved`、`declined`。デフォルト値 `pending`。「値セットで定義された値に選択リストを限定」をオン |
| 対応日時 | `HandledAt` → `HandledAt__c` | 日付/時間 | – |

### 1-5. CaseShelfリアクション

> すでに 1-1〜1-4 を作って CaseShelf を使っている場合は、この 1-5 と、手順2・3の「CaseShelfリアクション」の行だけを追加で設定してください。
> 作るまでの間は、CaseShelf の画面にリアクション欄が表示されないだけで、ほかの機能はそのまま使えます。

| 設定 | 値 |
|---|---|
| 表示ラベル | CaseShelfリアクション |
| 表示ラベル（複数形） | CaseShelfリアクション |
| オブジェクト名（API参照名） | `CaseShelf_Reaction` （→ `CaseShelf_Reaction__c`） |
| レコード名 | リアクション番号 |
| データ型 | **自動採番**、表示形式 `RA-{000000}` |

| 項目の表示ラベル | 項目名（API参照名） | データ型 | 設定 |
|---|---|---|---|
| 投稿 | `Post` → `Post__c` | **参照関係**（関連先: CaseShelf投稿） | 「参照レコードが削除された場合」→ **この項目の値を空白にします** |
| 絵文字 | `Emoji` → `Emoji__c` | テキスト | 文字数 16 |

> 投稿が削除されると、その投稿へのリアクションも CaseShelf が削除します（削除できなかった他の人のリアクションは、その人が次にログインしたときに削除されます）。

## 2. 共有設定（誰がどのレコードを見られるか）

**設定 → セキュリティ → 共有設定** →「組織の共有設定」の「編集」で、次のとおりにします。

| オブジェクト | デフォルトの内部アクセス権 |
|---|---|
| CaseShelf投稿 | **公開/参照のみ**（全員が見られる。編集・削除は投稿者本人と管理者だけ） |
| CaseShelf利用者 | **公開/参照・更新可能**（本人が表示名・プロフィール画像を変えられるようにするため。権限・状態・メールアドレスは手順3の項目レベルセキュリティで管理者だけが変更できるようにする） |
| CaseShelf保存 | **非公開**（自分の保存だけが見える） |
| CaseShelf利用依頼 | **非公開**（依頼した本人と管理者だけが見える） |
| CaseShelfリアクション | **公開/参照のみ**（全員が見られる。取り消せるのはリアクションした本人と管理者だけ） |

外部アクセス権は「非公開」のままで構いません。

## 3. 権限セットを作る

**設定 → ユーザー → 権限セット → 新規** で2つ作ります。ライセンスは「--なし--」で構いません。

### 3-1. CaseShelf利用者（`CaseShelf_Member`）— CaseShelf を使う全員に付ける

「オブジェクト設定」で次のとおりにします。

| オブジェクト | 参照 | 作成 | 編集 | 削除 | すべて表示 | すべて変更 |
|---|---|---|---|---|---|---|
| CaseShelf投稿 | ✓ | ✓ | ✓ | ✓ | | |
| CaseShelf利用者 | ✓ | | ✓ | | | |
| CaseShelf保存 | ✓ | ✓ | ✓ | ✓ | | |
| CaseShelf利用依頼 | ✓ | ✓ | | | | |
| CaseShelfリアクション | ✓ | ✓ | | ✓ | | |

項目レベルセキュリティ（各オブジェクトの「項目の権限」）:
- **CaseShelf投稿**: すべての項目を「参照アクセス権」「編集アクセス権」ともにオン
- **CaseShelf利用者**:
  - 「プロフィール画像」: 参照・編集ともにオン
  - 「メールアドレス」「権限」「状態」: **参照のみオン**（編集はオフ）
  - ※表示名（レコード名）は常に編集可能です
- **CaseShelf保存**: 「投稿」を参照・編集ともにオン
- **CaseShelf利用依頼**: すべての項目を参照・編集ともにオン
- **CaseShelfリアクション**: 「投稿」「絵文字」を参照・編集ともにオン

「タブの設定」は任意です（Salesforce 上でデータを見せたくなければ「使用不可」のまま）。

### 3-2. CaseShelf管理者（`CaseShelf_Admin`）— CaseShelf の管理者に追加で付ける

| オブジェクト | 参照 | 作成 | 編集 | 削除 | すべて表示 | すべて変更 |
|---|---|---|---|---|---|---|
| CaseShelf投稿 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| CaseShelf利用者 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| CaseShelf保存 | ✓ | ✓ | ✓ | ✓ | | |
| CaseShelf利用依頼 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| CaseShelfリアクション | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |

項目レベルセキュリティ: 5つのオブジェクトのすべての項目を、参照・編集ともにオン。

> 管理者が他の人の投稿の写真を差し替えたり投稿を削除したとき、元の写真ファイルの削除は、ファイルの所有者でないと失敗することがあります（投稿の内容は正しく更新・削除されます）。残ったファイルは Salesforce の「ファイル」タブから削除できます。

## 4. 権限セットを付ける

1. **CaseShelf利用者** の権限セットを、CaseShelf を使う可能性のある**全員**に付けます。
   権限セットの画面 →「割り当ての管理」→「割り当てを追加」で、複数のユーザーをまとめて選べます。
   - 未登録の人が「利用登録を依頼する」ときにも、この権限セットが必要です。
   - 新しく入社した人にも、Salesforce のユーザー作成時に付けてください。
2. **CaseShelf管理者** の権限セットを、CaseShelf の管理者に**追加で**付けます（利用者の権限セットと両方付けます）。

> CaseShelf を実際に使えるかどうか（利用者登録・利用停止）は、CaseShelf の管理者画面で管理します。権限セットは「Salesforce のデータにアクセスできるか」を決めるものです。

---

## 5. 最初の管理者でログインする

1. `src/config.js` の `initialAdminEmails` に、最初の管理者のメールアドレス（Salesforce と同じもの）が入っていることを確認します。
2. その人（**CaseShelf管理者** の権限セットを付けた人）が「Salesforceでログイン」します。
   CaseShelf利用者 のレコードが自動で作られ、管理者として使えるようになります。
3. 以降は、CaseShelf の管理者画面から利用者を登録します。

ほかの管理者を増やすときは、
- CaseShelf の管理者画面で「管理者」として登録する
- Salesforce で **CaseShelf管理者** の権限セットを付ける

の両方を行ってください。

---

## 6. デザイン担当者の自動入力

投稿画面で物件Noを入れて「Salesforceで検索」を押すと、次の順にたどってデザイン担当者を入力します。

商談 → 商談商品（商品名が `スペースデザイン課`・`グラフィックデザイン課`・`プランニング課` のもの）
→ プロジェクト管理（`Creative_Achievements__c`。項目「基案件」`Base_opportunity__c` で商談商品につながる）→ **所有者**

- 対象の部門・オブジェクト名・項目名は `src/config.js` の `designStaff` で変更できます。
- CaseShelf を使う人が、Salesforce の **商談・商談商品・商品・プロジェクト管理** を参照できる必要があります
  （通常の Salesforce の権限で参照できていれば、追加の設定は不要です）。
- 担当者が見つからない場合や違う場合は、投稿画面で手入力・修正できます。

## 7. うまくいかないとき

| 画面の表示 | 原因と対処 |
|---|---|
| 「Salesforceに CaseShelf 用のオブジェクトが見つかりません」 | 手順1のオブジェクトが無い、API参照名が違う、または権限セット（手順3・4）が付いていない |
| 「Salesforceのオブジェクト・項目の設定が正しくありません（No such column 'xxx'…）」 | 項目 `xxx` が無いか API 参照名が違う。または権限セットの項目レベルセキュリティで参照がオフ |
| 「この操作を行う権限がSalesforceにありません」 | 権限セットのオブジェクト権限・項目の編集権限を確認。他の人の投稿を編集・削除できるのは管理者（CaseShelf管理者 の権限セット）だけ |
| ログイン後、利用登録の画面になる（管理者なのに） | CaseShelf利用者 にその人のレコードが無い。`initialAdminEmails` に入っていれば、CaseShelf管理者 の権限セットを付けてからログインし直す |
| 「Salesforceと通信できませんでした」 | CORS の許可リストに、アプリのURLのオリジンが入っているか確認 |
| 投稿画面にデザイン担当者の入力欄が出ない | CaseShelf投稿 に `DesignStaff__c` が無いか、権限セットの項目レベルセキュリティで参照がオフ |
| 「デザイン担当者は取得できませんでした」 | プロジェクト管理・商談商品・商品を参照する権限が無いか、`src/config.js` の `designStaff` の名前が違う |
