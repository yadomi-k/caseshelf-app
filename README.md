# CaseShelf（社内事例写真アプリ）試作品

社内の案件写真を投稿・検索・閲覧するWebアプリです。
**投稿・写真・利用者などのデータは会社のSalesforceに保存され、CaseShelfの利用者全員が閲覧できます。**
（Salesforce側の準備は [docs/salesforce-setup.md](docs/salesforce-setup.md) を参照）

一覧には、昭栄美術の公開実績ページ（https://www.shoei-bijutsu.co.jp/works/）の掲載情報・画像をもとにした
**サンプル投稿14件**も表示されます（閲覧専用。アプリのコードに書かれたデータで、Salesforceには保存されません）。
不要になったら `src/config.js` の `showSamplePosts` を `false` にしてください。

## 1. 動かし方

このアプリは**ビルド不要**です（Node.js／npmがこの開発機に入っていなかったため、第1段階はReact
をCDNから読み込む構成にしています。詳しくは「6. 技術構成と制約」参照）。

```bash
cd <このREADMEがあるフォルダ>
python3 -m http.server 8787
```

ブラウザで `http://localhost:8787` を開いてください。Python以外でも、`index.html` を静的配信できる
サーバーであれば何でも動きます（VS Codeの Live Server 拡張、`npx serve` など）。

- データ（投稿・写真・利用者・保存・利用登録の依頼）は **Salesforce** に保存されます。どの端末・ブラウザから
  ログインしても同じデータが見えます。
- ブラウザに保存するのは、Salesforceへの接続情報（ログアウトまで。localStorage）と、検索条件・スクロール位置
  （タブを閉じるまで。sessionStorage）だけです。
- 他の人が投稿した内容は、ログイン時と、しばらくしてから画面に戻ったとき（1分以上たってから）に読み込み直します。
  すぐに見たいときはページを再読み込みしてください。

## 2. ログイン（試作品）

**ログインは基本的に「Salesforceでログイン」で行います。**（設定方法は下の「Salesforceでログイン」参照）

- CaseShelfを使うには、管理者による利用者登録が必要です。管理者画面で、その人がSalesforceに登録している
  メールアドレス・表示名・権限を登録します。パスワードは不要です。
- 利用停止中の利用者はログインできません。ログイン中に管理者が利用停止にした場合も、次の操作時に
  強制的にログアウトされます。

### 登録完了メール

管理者画面で利用者を登録すると（直接登録・依頼からの登録のどちらも）、画面上部に「登録完了メールを作成する」
ボタンが表示されます。押すとメールソフト（Outlook等）が開き、次の内容のメールが作成されるので、確認して送信してください。

- 宛先: 登録した人のメールアドレス
- 件名: 【CaseShelf】CaseShelfアカウント登録完了
- 本文: 「CaseShelfアカウント登録完了」のメッセージと「CaseShelfログインURL」（このアプリを開いているURL）

**試作品での制約:** サーバーを持たない構成のため、メールは自動では送信されません（ブラウザから直接メールを
送る手段がないため）。本番（サーバー付きの構成）では、登録と同時に自動送信できるようになります。

### 未登録の人からの利用登録の依頼

Salesforceでの本人確認はできたが、CaseShelfに登録されていない人には「利用登録がまだです」画面を表示します。

1. 本人が「管理者に利用登録を依頼する」を押すと、依頼が記録されます（同じ人の未対応の依頼は重複して作られません）
2. 続けて「依頼メールを作成する」を押すと、件名「【CaseShelf】アカウント作成依頼」、本文に氏名・メールアドレス・
   依頼日時が入ったメールが作成されます。宛先は `src/config.js` の `accountRequestEmail` で設定します
3. 管理者画面の「利用登録の依頼」に一覧が表示され、権限を選んで「登録する」か「見送る」を選べます。
   未対応の依頼がある間は、メニューの「管理者」に件数が表示されます

依頼はSalesforceに保存されるため、管理者画面の依頼一覧には全員の依頼が表示されます（管理者への自動通知は
行わないため、依頼メールも併用してください）。

### 最初の管理者

`src/config.js` の `initialAdminEmails` に書いたメールアドレスの人は、CaseShelfの利用者がまだ登録されていなくても、
初回ログイン時に自動で「管理者」として登録されます。Salesforce側で「CaseShelf管理者」の権限セットが必要です
（[docs/salesforce-setup.md](docs/salesforce-setup.md) の手順5）。

> 以前あった「管理者の緊急用ログイン（パスワード）」は廃止しました。データがSalesforceにあるため、
> Salesforceにログインできないときは、どの方法でもCaseShelfのデータにアクセスできないためです。

### Salesforceでログイン

ログイン画面の「Salesforceでログイン」から、会社のSalesforceアカウントでログインできます。

- Salesforceでログインした人のメールアドレスと、CaseShelfに登録されている利用者のメールアドレスを照合します。
  **CaseShelfに登録されていない人は、Salesforceのアカウントがあってもログインできません。**
- 利用停止中の利用者は、Salesforce経由でもログインできません。
- サーバーを持たない構成のため、コンシューマの秘密（Client Secret）は使わず、PKCE方式で保護しています。
- 取得したアクセストークンで、CaseShelfのデータをSalesforceに読み書きします。トークンは**ログアウトするまで**
  このブラウザ（localStorage）に保持し、ログアウト時に無効化します。Salesforceのセッションの有効期限が切れると、
  「もう一度ログインしてください」と表示されます。
- 読み書きできる範囲は、ログインした人のSalesforceの権限（権限セット・共有設定）で決まります。他の人の投稿を
  編集・削除できないことなどは、Salesforce側でも制限されます。

#### 使えるようにするための設定（Salesforceのシステム管理者が行う）

1. **接続アプリケーションを作成する**（設定 → アプリケーションマネージャ → 新規接続アプリケーション）
   - 「OAuth設定の有効化」をオンにする
   - コールバックURL: このアプリを開くURL（例: ローカルで試すなら `http://localhost:8787/`）。末尾の `/` まで完全に一致させる
   - 選択したOAuth範囲: 「一意のユーザー識別子へのアクセス（openid）」「ID URLサービスへのアクセス（id, profile, email, address, phone）」
     「API を使用してユーザーデータを管理（api）」（データの保存と物件Noでの商談検索に必要）
   - 「サポートされる認証フローにProof Key for Code Exchange (PKCE) 拡張を要求」をオン
   - 「Webサーバーフローの秘密が必要」はオフ
   - ※Salesforceのバージョンにより、「外部クライアントアプリケーション」として作成する画面になっている場合もあります。設定項目は同じです
2. **CORSを設定する**（設定 → CORS）
   - 許可リストに、このアプリのURLのオリジン（例: `http://localhost:8787`）を追加する
   - 「OAuthエンドポイントのCORSを有効化」をオンにする
   - ※同じ許可リストが、データの保存・商談検索（REST API）にも使われます
3. **アプリ側に設定する**: `src/config.js` に次を入力する
   - `myDomainUrl`: 会社の「私のドメイン」のURL（例: `https://xxxx.my.salesforce.com`）。`login.salesforce.com` は使えません
     （ブラウザからのトークン取得は私のドメインのURLでのみ許可されているため）
   - `clientId`: 接続アプリケーションの「コンシューマ鍵」
   - `salesforceOpportunity.propertyNoField`: 商談の「物件No」項目のAPI参照名（例: `PropertyNo__c`。
     設定 → オブジェクトマネージャ → 商談 → 項目とリレーション で確認）。**初期値は仮の値なので必ず確認してください**

既にログインしていた人は、`api` の範囲を追加した後、一度ログアウトしてログインし直すと商談検索が使えるようになります。

### 投稿画面: 物件Noから商談を検索

投稿画面の一番上で物件Noを入力し、「Salesforceで検索」（またはEnter）を押すと、Salesforceの商談を物件Noで
検索し、見つかった商談の内容を自動で入力します。

| 投稿画面の項目 | 入力される内容 |
|---|---|
| 案件名 | 商談の Name 項目 |
| Salesforce案件URL | 商談のページのURL（`https://<私のドメイン>/lightning/r/Opportunity/<Id>/view`） |

- 自動入力した後も、案件名・URLは手で修正できます。見つからない場合や接続できない場合は手入力してください。
- 物件Noは案件と一緒に保存され、案件詳細に表示されます。
- Salesforceのログインの有効期限（組織のセッションタイムアウト）が切れた場合は、ログインし直してください。

4. **CaseShelfのデータの保存先を作る**: [docs/salesforce-setup.md](docs/salesforce-setup.md) の手順で、
   カスタムオブジェクトと権限セットを作成・付与する

接続アプリケーションは作成後、反映まで数分かかることがあります。

## 3. 実装済みの機能（第1段階）

- 案件のカード一覧（新着順）。写真の下に案件名・説明の1行目・タグ（最大3つ）・投稿日・リアクションを表示し、文字が写真に重ならない。
  スマートフォン2列／タブレット・PC 3列（保存一覧・マイページは広い画面で4列）
- 複数写真案件へのバッジ表示、スクロールに応じた読み込み（無限スクロール風）
- タイムライン：新しい投稿から順に、投稿者・写真（スワイプで切り替え）・案件名・説明・タグを縦に並べて眺められる。
  その場でリアクション・保存ができ、下までスクロールすると続きを読み込む（一覧画面とは別の画面。下部／上部のメニュー「タイムライン」）
- 検索サイドバー：案件名・ハッシュタグのキーワード検索（`#`の有無を問わない）と、ハッシュタグ一覧（投稿数の多い順・件数付き）からの絞り込み、
  条件の解除。PCは一覧の左側に表示し、「検索・絞り込みを閉じる／開く」で切り替え（閉じた状態はブラウザに記憶し、カードは4列になる）。
  スマートフォンは「検索・絞り込み」ボタンで左から開く
- タグをクリックしてそのタグで絞り込み
- 一覧に戻った際の検索条件・スクロール位置の保持（検索条件ごとに保持）
- 案件詳細（写真を大きく表示、スマホはスワイプ・PCは矢印、現在の写真番号/総枚数）。
  PC（幅960px以上）は、写真を画面の左側いっぱいに、案件の内容を右側に並べて表示
- タグから一覧へ遷移、Salesforce案件URLがある場合のみ「Salesforceで案件を見る」ボタン表示
- 投稿画面で物件Noを入力してSalesforceの商談を検索し、案件名・Salesforce案件URLを自動入力
- 利用者の登録時に、本人宛ての登録完了メール（ログインURL入り）を作成
- 案件の新規投稿・編集（複数写真アップロード、並べ替え、代表写真の変更、削除）
- アップロード状況の表示（擬似プログレスバー）とエラー表示（非対応形式・サイズ超過・枚数超過）
- 投稿者本人（または管理者）のみ編集・削除可。削除は確認ダイアログを表示
- 保存（ブックマーク）、保存の解除、保存一覧画面（利用者ごとに非公開）
- 投稿へのリアクション（下の「投稿へのリアクション」参照）
- プロフィール画面（表示名・プロフィール画像の変更、自分の投稿一覧）
- 管理者画面（利用者の招待・停止／復帰、投稿とタグの管理・削除）
- 一般利用者は管理者画面にアクセスできない（アクセスするとURLを直接叩いても一覧へリダイレクト）
- 対象外機能（コメント・通知・DM・フォロー・ストーリーズ・リール・動画投稿・外部公開等）は
  画面上に一切表示していません

### 投稿へのリアクション

Slackのリアクションのように、投稿に絵文字でリアクションできます。

- 案件詳細の説明文の下にリアクション欄があります。顔のボタンを押すと絵文字の一覧（16種類）が開き、選ぶとリアクションが付きます。
- リアクションは **1つの投稿につき1人1つまで** です。別の絵文字を選ぶと、前のリアクションから付け替わります。
- 付いたリアクションは「絵文字＋人数」で表示されます。自分が付けたものは緑色の枠で表示され、もう一度押すと取り消せます。
  ほかの人が付けた絵文字を押すと、自分のリアクションをその絵文字にできます。
- 以前の版で1つの投稿に複数のリアクションを付けていた場合は、いちばん新しいものだけが数えられます
  （古いものは、その人が次にログインしたときに削除されます）。
- 「リアクションした人を見る」で、絵文字ごとに誰がリアクションしたかを表示します（PCでは絵文字にマウスを重ねても表示されます）。
- 一覧・保存一覧・マイページの写真の左上に、多い絵文字（最大3つ）とリアクションの合計数が表示されます。
- リアクションはSalesforceの「CaseShelfリアクション」に保存され、利用者全員が見られます（取り消せるのは本人だけ）。
  ほかの人のリアクションは、詳細画面を開いたとき・ログイン時・しばらくしてから画面に戻ったときに反映されます。
- 選べる絵文字は `src/data.js` の `REACTION_EMOJIS` で変更できます。
- サンプル投稿にはリアクションできません。
- Salesforceに「CaseShelfリアクション」を作るまでは、リアクション欄は表示されません（ほかの機能はそのまま使えます）。
  作り方は [docs/salesforce-setup.md](docs/salesforce-setup.md) の 1-5 を参照してください。

### PCでの表示サイズ

画面のサイズ（文字・余白・画面幅）はすべて `rem` で指定しており、`styles.css` 冒頭の `html { font-size: … }`
を変えるとまとめて拡大・縮小できます。現在は、スマートフォン 16px、PC（幅1024px以上）18px、大きな画面
（幅1600px以上）20px です。PCの一覧は、左に検索サイドバー、右に3列のカードを表示します。

## 4. 試作品としての割り切り・未実装事項

開発指示書 8章・9章に基づき、以下は意図的な割り切りです。実際の運用には第2段階での対応が必要です。

| 項目 | 試作品での扱い |
|---|---|
| ログイン・認証 | Salesforceでログイン。データへのアクセスはSalesforceの権限で制御される |
| データ保存先 | Salesforce（カスタムオブジェクト5つ＋ファイル）。利用者全員で共有 |
| 写真の保存 | 長辺1600pxのJPEGに縮小し、Salesforceのファイルとして保存（元の画像は保存しない） |
| アップロード進捗 | 写真の読み込み（縮小）までを表示し、Salesforceへの送信は「投稿する」を押したときに行う |
| 最新データの反映 | ログイン時・画面に戻ったとき（1分以上たってから）に読み込み直す（リアルタイム更新はしない） |
| 利用者招待 | 登録完了メールはメールソフトで作成し、管理者が送信する（自動送信はしない） |
| Salesforce連携 | 投稿時に物件Noで商談を検索し、案件名・URLを入力するのみ（その後の自動同期は行わない） |
| バックアップ・復元 | 未実装（第2段階の対象） |

### 写真の枚数・容量・対応形式の上限（提案・要確認）

開発指示書8章の指示に基づき、実装前の提案として以下の上限を試作品に仮実装しています。本番仕様として
確定する際はご確認ください。

- 1投稿あたり最大 **5枚**
- 1投稿あたりの合計容量は最大 **100MB**（選んだ元の画像ファイルの合計）
- 対応形式: JPEG / PNG / WEBP / GIF
- 投稿画面に「n / 5枚・合計 xxMB / 100MB」を表示し、上限を超える写真は追加できません

Salesforceのファイル保存容量を節約するため、保存する際に写真を長辺1600pxのJPEG（1枚おおよそ0.3〜0.6MB）に
縮小しています（GIFのアニメーションは1枚目だけになります）。1投稿あたり約3MB以下のため、月50件でも年2GB以下の見込みです。
元の画像のまま保存したくなった場合は、写真だけをSharePoint等に置く構成を検討します。

## 6. 技術構成と制約

この開発機には **Node.js／npmがインストールされていません**でした。そのため第1段階の試作品は、
ビルドツール（Vite/Webpack等）を使わず、ブラウザから直接動かせる構成にしています。

- React 18 / ReactDOM 18 / Babel Standalone を CDN から読み込み
- 画面はReact（`React.createElement`）で実装、ルーティングは `location.hash` を使った自作の簡易ルーター
- スタイルは素のCSS（`styles.css`）
- サンプル投稿14件の写真は、昭栄美術の公開実績ページ（shoei-bijutsu.co.jp/works/）に掲載されている
  画像を直接参照（ホットリンク）している。投稿した写真はSalesforceのファイルとして保存し、
  表示時にSalesforceのREST APIから取得している

**第2段階（本番機能）に進む際は、Node.jsのインストールを前提に、Next.js等のフレームワーク＋実際の
データベース（例: PostgreSQL等）・認証基盤・オブジェクトストレージへの置き換えを想定しています。**
外部サービスの契約・有料サービスの利用・公開前には、構成と費用を別途ご提示します。

```

styles.css           スタイル
src/config.js         設定（Salesforceの接続先・最初の管理者・サンプル表示）

src/sfdata.js         Salesforceへのデータの読み書き（投稿・写真・利用者・保存・リアクション・依頼）
src/data.js           写真の上限などの設定・サンプル投稿の定義
docs/salesforce-setup.md  Salesforce側の設定手順（オブジェクト・項目・共有設定・権限セット）
src/utils.js          共通ユーティリティ（タグ正規化等）
src/components.jsx    共有UIコンポーネント（グリッド・ナビ・モーダル等）
src/pages.jsx         画面コンポーネント（ログイン・一覧・詳細・投稿・保存・プロフィール・管理者）
src/app.jsx           ルーティング・状態管理・アクセス制御
```
